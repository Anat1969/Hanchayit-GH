# אפיון: הנחיות מרחביות אשדוד, מדריך תלת מימדי

## מטרה

ההנחיות המרחביות של אשדוד מוצגות במדריך אחד. מצד אחד הנוסח המלא, עם חיפוש. מצד שני מודל תלת מימדי של הנושא, שמראה מה המשמעות של כל מספר על מגרש ובניין.

## משתמשים

1. **אדריכלים ועורכי בקשות להיתר.** הם צריכים לדעת מה חל על הפרויקט שלהם, ולראות את המידות במקום לפרש אותן מהטקסט.
2. **צוות אדריכלית העיר.** משתמשים במדריך כדי להסביר הנחיות, ובהמשך כדי לבחון את ההשפעה של שינוי ערך לפני עדכון מהדורה.

## היקף גרסה 1

רק פרק ב' (עבודות הטעונות היתר). פרק א' ייכנס בגרסה 2, באותו מבנה נתונים.

## מסכים

### 1. המדריך (מסך יחיד, שלושה אזורים)

```
┌──────────────────────────────────────────────────────────────┐
│  חיפוש                                         [סוג מבנה ▾]  │
├───────────────────────┬───────────────────┬──────────────────┤
│                       │                   │                  │
│   מודל תלת מימדי      │   נוסח הסעיפים     │   תוכן עניינים   │
│   (גיליון)            │                   │                  │
│                       │                   │                  │
│   [תכנית][חתך][אקסו]  │                   │                  │
│   טבלת כותרת          │                   │                  │
└───────────────────────┴───────────────────┴──────────────────┘
          שמאל                  מרכז                ימין (RTL)
```

- **תוכן עניינים (ימין):** עץ הסעיפים לפי `sections`. בסעיף שיש לו סצנה מופיע סימן קטן של קובייה. לחיצה גוללת את הנוסח לסעיף.
- **נוסח (מרכז):** הסעיפים לפי הסדר. מספר הסעיף בשוליים הימניים, כמו במסמך רשמי. ערך מספרי מתוך `params` מוצג כ"ערך מקושר" (ראה DESIGN.md). ריחוף או פוקוס על הערך מדגיש את המידה במודל, ולהפך.
- **מודל (שמאל):** הסצנה של הסעיף הפעיל. הוא דביק (sticky) בגלילה ומתחלף כשסעיף עם סצנה אחרת נכנס לאזור הקריאה. כשאין סצנה, מופיע הגיליון האחרון שהוצג בגוון מעומעם, עם הכיתוב "לסעיף זה אין המחשה".
- **סוג מבנה:** צמודי קרקע, מגורים רוויה, חזית פעילה או תעשייה. הבחירה מסננת את הסעיפים לפי `applies_to`, וקובעת איזה ערך מקבלת הסצנה כשיש ערכים שונים לסוגים שונים. ברירת המחדל: הכל.

### 2. דף סעיף (`/rule/:id`)

כתובת קבועה לכל סעיף, כדי שאפשר יהיה לשתף קישור במייל או בהערה לבקשה. זה אותו מסך, כשהסעיף מסומן ופעיל.

### 3. מובייל

הנוסח מלא ברוחב המסך. המודל מופיע כפס עליון בגובה 40vh שאפשר לכווץ. תוכן העניינים נפתח מכפתור "סעיפים".

## חיפוש

- החיפוש מתבצע בצד הלקוח, עם MiniSearch, על `text` ועל `title` של הסעיף ושל הסצנה.
- **עברית:** נרמול שמוחק ניקוד, גרשיים וגרש, ומאחד ״ ו־" וגם ־ ו־-. הסרת תחיליות ו, ה, ב, ל, מ, ש, כ ושילובים שלהן (וה, שב, מה וכו') רק כשנשארות 3 אותיות לפחות. ההתאמה היא לפי תחילית, כך ש"גדר" מוצא גם את "גדרות".
- **מילים נרדפות** מתוך `synonyms.json`.
- **חיפוש לפי מספר סעיף:** הקלדה של "2.7.1" קופצת ישר לסעיף.
- **תוצאות:** רשימה מתחת לשדה. כל תוצאה מציגה מספר סעיף, כותרת, וקטע עם ההתאמה מודגשת. מקלדת: חיצים ו־Enter.
- **אין תוצאות:** "לא נמצא סעיף עבור 'X'", ומתחת עד שלושה מונחים קרובים מהמילים הנרדפות.

**הערות מידה:** קו מידה עם סימני חיתוך אלכסוניים, ערך ויחידה. המידה המגבילה (מקסימום או מינימום) מופיעה בצבע הגבול, ומידה תיאורית בצבע דיו.

## נאמנות לנתונים

הערכים בנוסח ובמודל הם תמיד הערכים של המהדורה המאושרת, כפי שהם ב־`data/*.json`. אין בממשק מצב לשינוי ערכים. מצב הבחינה שתוכנן כאן כשלב 4 נבנה והוסר לבקשת אדריכלית העיר (אוקטובר 2026). הערות הבדיקה (`review`) נשמרות בנתונים וב־`review-notes.md`.

## מחוץ להיקף בגרסה 1

- בדיקת תאימות של תכנית אמיתית (העלאת DWG או IFC).
- התחברות משתמשים.
- פרק א'.
- עריכת הנתונים מתוך הממשק. העריכה נעשית בקובץ JSON בגרסה 1.

## שלבים

1. **שלד ונתונים:** טעינה וולידציה של JSON, עץ תוכן, נוסח, חיפוש עברי, סינון לפי סוג מבנה, ניתוב לכל סעיף. **מוכן כש:** כל 146 הסעיפים מוצגים, החיפוש עובר את מבחני העברית ואין שגיאות ולידציה.
2. **מנוע סצנות וחמש סצנות ראשונות:** fence-street, retaining-terrace, pergola-ground, building-spacing, ground-floor-height. **מוכן כש:** כל מספר במודל מגיע מפרמטר, הקישור הדו־כיווני בין הערך בטקסט למידה במודל עובד, ושלוש התצוגות עובדות.
3. **שאר הסצנות.**
4. **מצב בחינה.** נבנה והוסר. ראו "נאמנות לנתונים".
5. **פרק א'.**
